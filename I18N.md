# Internationalization (i18n) Guide

## Overview

This application supports multiple languages for both frontend and backend.

## Supported Languages

- **English (en)** - Default
- **Hungarian (hu)** - Magyar
- **German (de)** - Deutsch

## Backend i18n

### Location
- Translation files: `server/locales/*.json`
- i18n module: `server/config/i18n.js`

### Usage in Backend

The backend automatically detects the user's language from:
1. Query parameter: `?lang=hu`
2. `Accept-Language` HTTP header

Example:
```javascript
const i18n = require('../config/i18n');

// In controller
const message = i18n.tReq(req, 'auth.errors.usernameExists');
```

### Adding New Backend Translations

1. Open `server/locales/en.json` (or other language file)
2. Add your translation key:
```json
{
  "auth": {
    "errors": {
      "newError": "Your error message here"
    }
  }
}
```
3. Use in code: `i18n.tReq(req, 'auth.errors.newError')`

### API Language Selection

**Method 1: Query Parameter**
```bash
POST http://localhost:3000/api/auth/login?lang=hu
```

**Method 2: HTTP Header**
```bash
POST http://localhost:3000/api/auth/login
Accept-Language: hu-HU,hu;q=0.9,en;q=0.8
```

## Frontend i18n

### Location
- Translation files: `frontend/src/assets/i18n/*.json`
- Translation service: `frontend/src/app/services/translation.service.ts`
- Translation pipe: `frontend/src/app/pipes/translate.pipe.ts`

### Usage in Frontend

**In TypeScript:**
```typescript
import { TranslationService } from './services/translation.service';

constructor(private translationService: TranslationService) {}

getMessage() {
  return this.translationService.translate('auth.login');
}

changeLanguage(lang: string) {
  this.translationService.setLanguage(lang);
}
```

**In Templates (with pipe):**
```html
<h1>{{ 'auth.login' | translate }}</h1>
<button>{{ 'auth.register' | translate }}</button>
```

### Adding New Frontend Translations

1. Open `frontend/src/assets/i18n/en.json`
2. Add your translation:
```json
{
  "myFeature": {
    "title": "My Feature Title",
    "description": "Description text"
  }
}
```
3. Use in template: `{{ 'myFeature.title' | translate }}`

### Language Persistence

The selected language is stored in `localStorage` and persists across sessions.

## Adding a New Language

### Backend

1. Create new file: `server/locales/fr.json`
2. Copy structure from `en.json`
3. Translate all values
4. Restart server - new language auto-detected

### Frontend

1. Create new file: `frontend/src/assets/i18n/fr.json`
2. Copy structure from `en.json`
3. Translate all values
4. Update `translation.service.ts`:
```typescript
getSupportedLanguages(): { code: string; name: string }[] {
  return [
    { code: 'en', name: 'English' },
    { code: 'hu', name: 'Magyar' },
    { code: 'de', name: 'Deutsch' },
    { code: 'fr', name: 'Français' }  // Add new language
  ];
}
```
5. Rebuild frontend: `npm run build:frontend`

## Testing Translations

### Test Server Configuration
```bash
# Get server configuration
curl http://localhost:3000/api/config

# Expected response:
{
  "success": true,
  "data": {
    "defaultLocale": "en",
    "supportedLocales": ["en", "hu", "de"],
    "environment": "development"
  }
}
```

### Test Backend API
```bash
# English (default)
curl http://localhost:3000/api/auth/login -d '{"username":"test"}' -H "Content-Type: application/json"

# Hungarian
curl http://localhost:3000/api/auth/login?lang=hu -d '{"username":"test"}' -H "Content-Type: application/json"

# German
curl http://localhost:3000/api/auth/login -d '{"username":"test"}' -H "Content-Type: application/json" -H "Accept-Language: de"
```

### Test Frontend
1. **Clear localStorage and test server default:**
   - Open browser developer tools
   - In console: `localStorage.removeItem('language')`
   - Refresh page
   - Language should match server's DEFAULT_LOCALE setting

2. **Test language switching:**
   - In console: `localStorage.setItem('language', 'hu')`
   - Refresh page
   - All text should be in Hungarian

3. **Test server config fetch:**
   - In console: `fetch('/api/config').then(r => r.json()).then(console.log)`
   - Should show server configuration including defaultLocale

### Change Server Default Language

1. Edit `.env` file:
```env
DEFAULT_LOCALE=hu  # Change to Hungarian
```

2. Restart your server

3. Clear frontend localStorage:
```javascript
localStorage.removeItem('language')
```

4. Refresh page - should now default to Hungarian

## Translation Key Naming Convention

Use dot notation for hierarchical organization:
- `auth.login` - Authentication related
- `errors.notFound` - Error messages
- `dashboard.welcome` - Dashboard features
- `common.save` - Common/shared translations

## Best Practices

1. **Keep keys descriptive**: Use `auth.errors.invalidPassword` not `err1`
2. **Group logically**: Related translations under same parent key
3. **Maintain consistency**: Same structure across all language files
4. **Fallback to key**: If translation missing, key is displayed
5. **Update all languages**: When adding new key, add to all language files

## Default Language

The default language is controlled by the server via environment variables:

**Server Configuration (`.env`):**
```env
DEFAULT_LOCALE=en
```

Change this value to set the default language:
- `DEFAULT_LOCALE=en` - English
- `DEFAULT_LOCALE=hu` - Hungarian
- `DEFAULT_LOCALE=de` - German

**How It Works:**
1. Server loads `DEFAULT_LOCALE` from `.env` on startup
2. Frontend fetches server configuration via `GET /api/config` on initialization
3. Frontend uses server's default if no language is saved in localStorage
4. User's language preference (localStorage) overrides server default

**API Endpoint:**
```bash
GET /api/config
Response:
{
  "success": true,
  "data": {
    "defaultLocale": "en",
    "supportedLocales": ["en", "hu", "de"],
    "environment": "development"
  }
}
```

**Priority Order:**
1. User's saved preference (localStorage) - highest priority
2. Server's DEFAULT_LOCALE from .env
3. Hardcoded fallback 'en' - lowest priority
